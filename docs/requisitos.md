Documento de Requisitos

Requisitos Funcionais (RF)

ID | Descrição | Prioridade 

| **RF01** | O sistema deve permitir o cadastro de usuários (Alunos e Monitores) com e-mail institucional. | Alta |
| **RF02** | O monitor deve conseguir cadastrar seus horários de disponibilidade vinculados a uma disciplina. | Alta |
| **RF03** | O aluno deve conseguir visualizar a lista de monitorias disponíveis filtrando por disciplina. | Alta |
| **RF04** | O aluno deve conseguir agendar uma sessão de monitoria escolhendo um horário vago. | Alta |
| **RF05** | O monitor e o aluno devem poder cancelar um agendamento com antecedência mínima de 2 horas. | Média |
| **RF06** | O monitor deve conseguir alterar o status do atendimento para "Concluído" após a sessão. | Média |

Requisitos Não-Funcionais (RNF)

ID | Descrição | Prioridade 

| **RNF01** | **Usabilidade:** A interface deve ser simples, responsiva e acessível via navegadores web em celulares e computadores. | Alta |
| **RNF02** | **Desempenho:** O sistema deve processar a confirmação de agendamento em menos de 2 segundos. | Média |
| **RNF03** | **Segurança:** As senhas dos usuários devem ser armazenadas utilizando algoritmos de hash seguros. | Alta |
| **RNF04** | **Documentação:** O projeto deve utilizar a linguagem Markdown para toda a sua documentação no GitHub. | Alta |
